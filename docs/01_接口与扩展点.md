# 接口与扩展点

## 四层模型接入边界

```text
标准 SourceSnapshot
  ├─ ModelInputAdapter ──> 地震/测井/轨迹张量
  ├─ Registration/Fusion ─> 对齐、质量、置信度和融合特征
  └─ PredictionRunner ───> 标准结果与可视化图层
```

1. **解释任务**：`src/well_seismic/interpretation/registry.py` 中的
   `InterpretationTaskSpec`，外部入口点为 `well_seismic.interpretation_tasks`；
2. **模型规格**：`src/well_seismic/modeling/contracts.py` 的 `ModelSpec`，入口点为
   `well_seismic.plugins`；
3. **输入适配器**：实现 `capabilities()`/`prepare()`，入口点为
   `well_seismic.input_adapters`；
4. **预测运行器**：注册 `model_id -> runner`，入口点为
   `well_seismic.prediction_runners`；
5. **井震融合**：实现 `fit`、`transform`、`fit_transform`、`state_dict`、
   `load_state_dict`，入口点为 `well_seismic.fusion_strategies`。

## HTTP 合同

前端保持同源 `/api/v1` 调用，不改 URL 或字段：

- `GET /api/v1/health`：服务与 `runtime_mode`；
- `GET /api/v1/capabilities`：任务、模型、适配器、运行器、数据流和图层合同；
- `GET /api/v1/projects`、`/projects/{id}/snapshots`、`/snapshots/{id}`：快照血缘；
- `POST /api/v1/data-preparation/tasks`、`/registration/tasks`、`/sample-building/tasks`：
  通用数据流程；
- `POST /api/v1/prediction/tasks`：`task_id` + `model_id` + `options` 的统一请求；
- `GET /api/v1/tasks/{task_id}`：持久化任务状态；
- `GET /api/v1/releases`：只读发布合同（无权重时 artifact 为 missing）；
- `GET /api/v1/system/cache`、`POST /api/v1/system/cache/clear`：可重建缓存；
- `GET /统一数据可视化`：同源可视化页面。

接口版提交任务模型时会返回 422 结构化错误（模型当前不可运行），不会返回虚假的
task id，也不会隐式搜索其他 checkout 的权重。

## 外部扩展要求

扩展包必须携带 `model_id`、版本、输入/输出轴序、来源/许可、权重 SHA-256、
训练/适用范围与运行时依赖；把二进制放入 `models/task-models/<model_id>/<version>/`，
用 entry point 注册后再执行隔离验证。通过验证后，显式设置
`WELLFUSE_MODEL_MODE=full_runtime`；保留 `interfaces/model_registry.json` 的稳定 ID。
